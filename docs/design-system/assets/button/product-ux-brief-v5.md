# Button Documentation Cover — Slate Surface Correction

## User goal

Open the Button specification without encountering a large white surface that breaks the dark documentation flow and causes visual strain.

## Stable frame

Preserve the accepted title, definition, substantial specimen box, full-width live Button, Intent/State/Size summaries, responsive structure, and every later documentation chapter.

## Initially visible

The same PDF-derived information hierarchy remains. Only the framed showcase material changes from a copied white continuation surface to a restrained Slate panel with readable nested summaries.

## Desktop and mobile

At desktop, the panel must remain clearly bounded without becoming a bright slab. At exactly 390px, the panel and stacked summaries must remain fully visible with no horizontal page overflow.

## Keyboard and accessibility

The live Button retains native semantics, crisp white label ink, and an unclipped focus-visible ring. Summary labels and values retain readable contrast on the dark panel.

## Visual craft and Slate fit

Use the canonical raised Slate surface, strong boundary, elevated summary surfaces, primary ink for summary labels, and readable secondary ink for values. Keep the panel flat: no gradient, glow, or decorative shadow. The PDF's white frame served its transition into later white pages; the web documentation remains dark, so copying that material is not faithful translation.

## Scope and approval triggers

Allowed: Button cover surface and nested summary contrast, versioned sanitized cover evidence, focused documentation verification, and the release record. Changing the Button component, cover structure or wording, shared documentation shell, later chapters, or other component pages requires renewed approval.
